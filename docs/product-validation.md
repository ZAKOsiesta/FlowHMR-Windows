# 剪辑视频与配套相机：依赖与验证范围

单人跨镜头动作连接、按需恢复原片相机、人机配套导出及相关 MCP 接口均复用现有的核心推理模型。本文档说明这些新增功能的依赖要求、已验证范围与已知限制。

---

## 1. 依赖项与环境要求

- **切镜检测（`scenedetect`）**：
  - Windows 安装入口为 `requirements-windows.txt`（包含 `tools/web/requirements.txt`）。自动切镜检测新增 `scenedetect>=0.6.7,<0.7`，Windows 约束文件锁定为 `0.6.7.1`。MCP、FBX SDK、接触修正组件及主推理模型沿用原有安装方式。
  - 若运行环境中缺少 `scenedetect` 或未能完整读取所选视频区间，任务会自动回退到原单段生成流程，并在 `shot_linking_report` 中记录原因。`check_install.py` 会提示该可选依赖缺失以便用户补齐，但不会阻断基础环境的 `ready` 状态。
- **图像重力估计（`GeoCalib`）**：
  - 运动相机观测沿用 VGGT。原片机位的图像重力估计由随仓库内置的 `third_party/geocalib_inference` 提供，`kornia==0.8.1` 与 `kornia_rs==0.1.9` 已纳入安装清单与 Windows 锁定文件。模型管理界面与命令行支持官方权重下载、完整性校验及本地文件夹导入。
  - 无论是运动相机模式还是默认固定机位模式（生成阶段仍跳过 VGGT），在按需恢复原片机位时均会调用 GeoCalib。当权重缺失/损坏、组件加载失败、设备不支持或单镜头估计不稳定时，系统会自动回退至“人物倾斜 + 地面约束”估计，并在任务完成摘要、原片机位视图及导出报告中明确标记降级；纯动作生成不受缺少 GeoCalib 的影响。详见 [GeoCalib 说明](geocalib.md)。
- **HaMeR 隔离子进程路径**：
  - 当系统运行库通过 `PYTHONPATH` 提供时，HaMeR 隔离子进程会保留 `-I` 隔离标志并优先继承父进程实际的 PyTorch 所在目录；具名运行环境的选择方式保持不变（目前已在 Windows + CUDA 下验证，假定 `torch` 与 `torchvision` 位于同一目录）。

## 3. 已知限制与设备边界

- **仅支持单人跨镜头连接**：多人模式遇到切镜时不执行连接；单人跨镜头连接在各镜头中选取画面占比最大的人物，暂不做跨镜头身份重识别（Re-ID）。
- **画外肢体与遮挡**：画面外肢体依赖模型先验估计，半身/特写镜头首尾朝向噪声较大；关节投影在画内也不等于未被遮挡。不足 15 帧的生成段保留为空档，不作插值补全。
- **多人重叠、交叉与遮挡对相机的干扰**：即便只选单人，配套相机仍依赖从所选人物检测/跟踪框提取的 SAM 关节观测来对齐动作并做稳定性门控。当多人重叠、交叉或严重遮挡时，检测框偏移、跟踪串人或遮挡下的姿态推断误差可能传导至恢复相机的位置、尺度、朝向与稳定性（GeoCalib 仅提供图像重力，无法解决人物关节归属问题）。因此相机完成状态、`trusted` 标签或 `quality.degraded=false` 不能作为遮挡场景无瑕疵的保证。详见 [配套相机限制](paired-camera.md#person-overlap-and-occlusion)。
- **配套相机性质与尺度**：恢复相机与最终动作配套自洽，并非物理标定；位移尺度依赖全片统计，无大范围移动镜头时退回以人物为锚点的定点慢速旋转兜底，尚未实现基于场景深度的尺度判据。
- **重定向残差与格式近似**：换体型后脚底仍可能存在轻微穿地或滑动；非等比例缩放根位移时不支持配套相机；VMD 整数视角与 FBX 平均焦距属于格式本身的近似。
- **设备覆盖范围**：设置页与运行环境界面已明确标注“跨镜头连接”和“原片机位恢复”目前仅在 NVIDIA CUDA 上完成验证，CPU、AMD ROCm 与 Intel XPU 上尚待实测。干净 Windows 环境首次安装生成及新版完整包升级后的完整生成复测清单详见 [Windows 发行版维护者复测清单](release-validation.md)。

## 4. 常用自检命令

在仓库根目录下启用目标运行环境后，可执行以下检查：

```powershell
python tools/windows/check_install.py --json
python -m unittest discover -s tests -v
node tools/check_locales.mjs
node tools/check_frame_sample.mjs
node --experimental-vm-modules tools/check_desktop_startup.mjs
```
