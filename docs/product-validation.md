# 剪辑视频与配套相机：依赖和验证范围

单人跨镜头连接、按需恢复原片相机、配套导出及相关 MCP 接口复用现有推理模型。以下说明对应这些新增路径的测试范围；其他设备和发行包的支持情况应以对应版本的实际验证为准。

## 依赖

Windows 安装入口为 `requirements-windows.txt`，其中包含 `tools/web/requirements.txt`。自动切镜新增 `scenedetect>=0.6.7,<0.7`，约束文件固定为 `0.6.7.1`。MCP、FBX SDK、接触修正组件和主要模型继续沿用原安装方式。

自动切镜缺少依赖或未完整读出所选区间时，任务会回退原路径，并在 `shot_linking_report` 写明原因。回退不代表素材没有切镜。安装检查仍会指出依赖缺失，方便补齐连接功能。

运动相机沿用 VGGT。**GeoCalib 是可选依赖，目前没有纳入安装、模型下载或发行打包流程。** 现有可选加载入口要求 `third_party/GeoCalib` 源码和 `models/geocalib/pinhole.tar` 权重，再从该源码及 `optional_packages/geocalib` 查找依赖；仅安装模块不会启用它。缺失、设备不支持或重力证据不稳定时，使用人物倾斜连续性和地面约束回退。普通安装应按没有 GeoCalib 的行为评估，不能用手动安装 GeoCalib 的测试结果代替。

若系统运行库通过 `PYTHONPATH` 提供，HaMeR 的隔离子进程使用父进程实际 PyTorch 所在目录；保留 `-I` 隔离设置。单独安装的具名运行环境仍按原方式选择。该兼容路径在 Windows CUDA 上验证，未验证 ROCm/XPU 的系统运行库组合。

## 已执行的验证

验证环境为 Windows build 26200、Python 3.10.20、NVIDIA RTX PRO 4500 Blackwell、PyTorch 2.8.0+cu128、torchvision 0.23.0+cu128、NumPy 1.26.4、SciPy 1.15.3、PySceneDetect 0.6.7.1、MCP 1.28.0 和 Flask 3.1.3。完整生成证据来自一台已有 Python、模型权重和 CUDA 环境的机器，不能视为干净机器安装验证。

| 检查 | 已有证据与边界 |
|---|---|
| 原路径冷启动 | 新进程、新上传、180 帧无切镜任务完成检测、VGGT、SAM、Flow、接触修正和 HaMeR；左右手各覆盖 180 帧 |
| 连接路径重新生成 | 1064 帧真实素材复用检测、可见性、相机及 SAM 缓存后，实际完成 5 段 Flow/接触修正/HaMeR，共 788 个有效帧；9 个不足 15 帧的区间保留为空档 |
| 局部镜头的连续性 | 3056 帧素材使用冻结输入重新生成，2950 有效帧；原画外关节误分段点的水平根位移为 5.63 mm，低于相邻镜头内位移 p99 18.96 mm。可见真实跳剪的合成测试仍能分段 |
| 切镜失败回退 | 缺依赖与读取不完整分别回退原路径，利用固定输入完成 180 帧 Flow/接触修正/HaMeR，动作 NPZ 与原固定输入结果逐字节一致；取消和意外异常不会被吞掉 |
| 原任务导出与固定条件生成 | 18 份历史导出逐字节比较、两段固定条件动作重算已有通过记录；这些是对应实现版本的历史回归，不能替代每次变更后的适用检查 |
| 冷启动重复性 | 上游自身的 SAM 冷启动结果存在数值波动。检查新增观测请求时，有/无请求的 token 最大差 0.073，小于同设置重复提取的 0.130；此局部比较不保证所有视频相同 |
| 相机及导出 | 已完成 NPZ/VMD/FBX 配套导出、相机回读、空档和逐帧同步检查；误差与格式、素材和角色相关，见 [配套相机说明](paired-camera.md) |
| 自动化与界面 | 已验证 22 个 MCP 工具、取消/重试、七语言键和占位符一致性。自动检查不能代替完整界面操作和语言审校 |

固定条件生成的逐字节比较与冷启动波动是不同检查。FBX 的文件元数据可能造成字节差异，动画内容应通过骨架、时间、单位、轴向及逐帧矩阵回读判断；读回一致不代表材质、蒙皮或帧间曲线均已检查。

## 已知限制与待验证项目

- 多人加切镜暂不连接。单人连接在其他镜头选择画面最大的人物，不做跨镜头身份识别。
- 画外肢体来自模型估计。只拍局部、遮挡或朝向不清时仍可能出错；投影在画内也不代表没有遮挡。少于 15 帧的生成段保留为空档，不生成补全。
- 原片相机与最终动作配套，不是物理标定。逐镜头可信度只反映当前证据，不保证真实尺度或所有人物投影准确。
- 相机尺度规则依赖全片统计，没有大行程镜头时使用定点兜底。基于场景深度的全片尺度判据尚未实现。
- 无 GeoCalib 时使用人物/地面回退；回退版完整视频的视觉评估仍未完成。
- 换体型后的脚底仍有残差。一个 PMX 样本最深约 17.24 mm，不能承诺跨角色零穿地。非等比例根位移不支持配套相机。
- 新路径以及受影响的原路径尚未完成 CPU、ROCm、Intel XPU 的实际生成验证。单元测试或 CPU 张量运算不等于设备端到端验证。
- 修复后固定视角、原片机位和另一 PMX 角色的全片视觉评估尚未完成。逐有效生成区间去掉整体水平旋转和平移后，22 个身体关节 p99 ≤ 5 mm 的比较仍待重测。
- 未完成从干净源码构建发行包、干净机器安装后的冷启动、GeoCalib 的发行方案，以及更新器补齐新依赖的验证。应从干净克隆构建发行包，保留上游对干净子模块的要求。

## 复查命令

在仓库根目录启用目标运行环境后执行：

```powershell
python tools/windows/check_install.py --json
python -m unittest discover -s tests -v
node tools/check_locales.mjs
node tools/check_frame_sample.mjs
```

安装检查覆盖依赖导入、实际设备矩阵运算与 NMS、必要模型及可选组件，不能代替完整生成。帧边界检查覆盖小数帧、切镜、空档和首尾，仍需实际播放和导出回读。

`tools/p0_regression.py` 提供 `record`、`check`、`compare`；使用独占创建保存基线，检查不覆盖基线，同时报告文件字节与数组摘要。

`tools/compare_fbx_readback.py LEFT.fbx RIGHT.fbx --report report.json` 使用 FBX SDK 比较骨架、单位、轴向、时间和整数帧全局矩阵。工具保留字节差异且退出码仍按严格字节标准判定；内容一致性需查看报告中的读回结果。它不覆盖材质、网格、帧间插值或渲染质量。
