# 剪辑视频与配套相机：依赖与验证范围

单人跨镜头动作连接、按需恢复原片相机、人机配套导出及相关 MCP 接口均复用现有的核心推理模型。本文档汇总这些新增功能的依赖项、已完成测试及已知边界。

---

## 1. 依赖项与环境要求

- **切镜检测（`scenedetect`）**：
  - Windows 安装入口为 `requirements-windows.txt`（包含 `tools/web/requirements.txt`）。自动切镜检测新增 `scenedetect>=0.6.7,<0.7`，Windows 约束文件锁定为 `0.6.7.1`。MCP、FBX SDK、接触修正组件及主推理模型沿用原有安装方式。
  - 若运行环境中缺少 `scenedetect` 或未能完整读取所选视频区间，任务会自动回退到原单段生成流程，并在 `shot_linking_report` 中记录原因。`check_install.py` 会提示该可选依赖缺失以便用户补齐，但不会阻断基础环境的 `ready` 状态。
- **图像重力估计（`GeoCalib`）**：
  - 运动相机观测沿用 VGGT。原片机位的图像重力估计由随仓库内置的 `third_party/geocalib_inference` 提供，`kornia==0.8.1` 与 `kornia_rs==0.1.9` 已纳入安装清单与 Windows 锁定文件。模型管理界面与命令行支持官方权重下载、完整性校验及本地文件夹导入（不再读取早期研究目录 `third_party/GeoCalib` 或 `optional_packages/geocalib`）。
  - 无论是运动相机模式还是默认固定机位模式（生成阶段仍跳过 VGGT），在按需恢复原片机位时均会调用 GeoCalib。当权重缺失/损坏、组件加载失败、设备不支持或单镜头估计不稳定时，系统会自动回退至“人物倾斜 + 地面约束”估计，并在任务完成摘要、原片机位视图及导出报告中明确标记降级；纯动作生成不受缺少 GeoCalib 的影响。详见 [GeoCalib 集成说明](geocalib.md)。
- **HaMeR 隔离子进程路径**：
  - 当系统运行库通过 `PYTHONPATH` 提供时，HaMeR 隔离子进程会保留 `-I` 隔离标志并优先继承父进程实际的 PyTorch 所在目录；具名运行环境的选择方式保持不变（目前已在 Windows + CUDA 下验证，假定 `torch` 与 `torchvision` 位于同一目录）。

## 2. 已完成的验证

本地测试环境：Windows (Build 26200) · Python 3.10.20 · NVIDIA RTX PRO 4500 Blackwell · PyTorch 2.8.0+cu128 · torchvision 0.23.0+cu128 · NumPy 1.26.4 · SciPy 1.15.3 · PySceneDetect 0.6.7.1 · Kornia 0.8.1 / Kornia-rs 0.1.9 · MCP 1.28.0 · Flask 3.1.3。

| 验证类别 | 实测内容与结果 |
|---|---|
| **自动化与回归测试** | 全量 **195 项**单元测试（`30.148 秒`）、7 种语言 1007 个词条与占位符检查、小数帧/切镜/空档边界采样检查、桌面启动握手检查全部通过。 |
| **原路径冷启动** | 新进程、新上传一段 180 帧无切镜视频（不复用任何历史缓存），完整跑通检测、VGGT、SAM、FlowHMR、接触修正与 HaMeR，左右手各覆盖 180 帧。 |
| **CPU 原路径对照** | 同一段 32 帧无切镜视频在禁用 CUDA 的独立进程中，分别用上游 `main` 与当前版本跑完检测、SAM、FlowHMR、接触修正与导出（模型参数与缓冲区均确认在 CPU）。当前版本自动切镜判定走原路径，输出的动作 NPZ 与上游逐字节一致（覆盖固定机位、无 HaMeR 原路径）。 |
| **跨镜头分段与碎段过滤** | 1064 帧（8 镜头）真实素材复用检测、相机及 SAM 缓存后，完成 5 段 FlowHMR / 接触修正 / HaMeR 生成（共 788 有效帧，左右手报告各 788 帧）；9 个不足 15 帧的碎区间（共 27 帧）按设计转为时间轴空档。 |
| **局部特写连续性修复** | 3056 帧素材基于冻结输入重生成 2950 有效帧；原画外关节误切点（第 513 帧）的水平根位移降至 `5.63 mm`（低于相邻镜头内位移 p99 的 `18.96 mm`），首段连续保持在 `[63, 1561)`；合成的真实跳剪测试仍能正常切开。 |
| **切镜异常回退** | 分别注入“缺少依赖”与“读取不完整”故障，均能正常回退原路径并基于固定输入完成 180 帧生成，动作 NPZ 与基准逐字节一致；主动取消与未预期异常正常向上抛出。 |
| **GeoCalib 相机恢复** | 3056 帧冻结动作上实跑图像重力与相机恢复，53 个拟合镜头中 52 个采用图像重力、1 个触发稳定性回退；836 帧真实固定机位任务实跑恢复，单镜头正常采用图像重力（方向离散角约 `0.530°`）；模拟缺失或截断权重时均正确降级回退，且不改动任何动作文件字节。 |
| **导出、回读与 MCP** | 18 份历史导出文件对比、带空档 VRMA 读回、NPZ/VMD/FBX 配套相机导出与逐帧同步、22 个 MCP 工具状态查询/取消/重试均验证通过。 |

## 3. 已知限制与待维护者复测范围

- **仅支持单人跨镜头连接**：多人模式遇到切镜时不执行连接；单人跨镜头连接在各镜头中选取画面占比最大的人物，暂不做跨镜头身份重识别（Re-ID）。
- **画外肢体与遮挡**：画面外肢体依赖模型先验估计，半身/特写镜头首尾朝向噪声较大；关节投影在画内也不等于未被遮挡。不足 15 帧的生成段保留为空档，不作插值补全。
- **多人重叠、交叉与遮挡对相机的干扰**：即便只选单人，配套相机仍依赖从所选人物检测/跟踪框提取的 SAM 关节观测来对齐动作并做稳定性门控。当多人重叠、交叉或严重遮挡时，检测框偏移、跟踪串人或遮挡下的姿态推断误差可能传导至恢复相机的位置、尺度、朝向与稳定性（GeoCalib 仅提供图像重力，无法解决人物关节归属问题）。因此相机完成状态、`trusted` 标签或 `quality.degraded=false` 不能作为遮挡场景无瑕疵的保证。详见 [配套相机限制](paired-camera.md#person-overlap-and-occlusion)。
- **配套相机性质与尺度**：恢复相机与最终动作配套自洽，并非物理标定；位移尺度依赖全片统计，无大范围移动镜头时退回以人物为锚点的定点慢速旋转兜底，尚未实现基于场景深度的尺度判据。
- **无 GeoCalib 回退表现**：缺少 GeoCalib 时采用人物倾斜与地面约束回退（在《寄明月》多切镜全片样本上存在较明显的地面倾角偏差），界面与报告会明确标注降级。
- **重定向残差与格式近似**：换体型后脚底仍可能存在轻微穿地或滑动（某 PMX 样本最大约 `17.24 mm`）；非等比例缩放根位移时不支持配套相机；VMD 整数视角与 FBX 平均焦距属于格式本身的近似。
- **跨镜头姿态精度与上游接触策略说明**：在 3056 帧样本的 3 个有效生成区间上（逐段仅对齐一次整体水平旋转与平移），与早期研究存档对比 22 个身体关节的 `p99` 差值为 `11.653 / 0.027 / 0.047 mm`（第二、三段已低于 `5 mm`）。首段超限的 34 帧集中在 `50.17–51.30 s`，原因是早期研究存档使用了本地修改的脚底接触重规划（`_replan_contacts`），而正式代码保持与上游一致的 `_keep_contact_timing`。在统一采用上游接触后处理的控制对照中，首段 `p99` 为 `0.061925 mm`。
- **设备覆盖声明**：设置页与运行环境界面已明确标注“跨镜头连接”和“原片机位恢复”目前仅在 NVIDIA CUDA 上完成验证，CPU、AMD ROCm 与 Intel XPU 上尚待实测。
- **待维护者协助的发行复测**：由于本地 Windows Sandbox 存在微软 WebView2 / Edge 安装器环境报错（`0x80040902`），且旧版在线更新会保留运行中的旧版 `FlowHMR.exe`，干净 Windows 系统的首次安装/完整生成以及使用新版完整包启动器的升级后完整生成，已整理至 [Windows 发行版维护者复测清单](release-validation.md) 交由上游维护者协助复核。

## 4. 常用复查命令与对比工具

在仓库根目录下启用目标运行环境后，可执行以下检查：

```powershell
python tools/windows/check_install.py --json
python -m unittest discover -s tests -v
node tools/check_locales.mjs
node tools/check_frame_sample.mjs
node --experimental-vm-modules tools/check_desktop_startup.mjs
```

- **动作回归对比（`tools/p0_regression.py`）**：提供 `record`、`check`、`compare` 子命令，以独占方式创建并保存基线（`check` 不会覆盖已有基线），同时输出文件字节与数组统计摘要。
- **FBX 动画内容回读对比（`tools/compare_fbx_readback.py`）**：由于 FBX 导出时可能因时间戳等文件元数据产生二进制字节差异，可使用 `python tools/compare_fbx_readback.py LEFT.fbx RIGHT.fbx --report report.json` 调用 FBX SDK 逐帧比对骨骼层级、单位、轴向、时间范围及整数帧全局变换矩阵（工具退出码仍按严格字节一致判定，具体动画内容是否一致请查看输出的 JSON 报告）。
