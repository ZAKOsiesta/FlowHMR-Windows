# Windows 发行版维护者复测清单

本文档整理了本 PR 在正式打包发布前，仍需上游维护者协助在干净环境与实机上复测的事项。

---

## 1. 为什么需要协助复测（本地环境说明）

1. **Windows Sandbox 的 WebView2 安装器环境异常**：
   - 在本地无预装 Python 的 Windows Sandbox 中测试首次启动时，随包 Python 解释器与新增依赖元数据均检查通过，但微软官方 WebView2 安装程序返回错误码 `0x80040902`（内部 `code 11`，提示无法创建临时目录）。
   - 在同一 Sandbox 中单独运行系统自带的 Edge 浏览器更新也报完全相同的 `0x80040902` 错误，而实际探测临时目录可写且磁盘空间充足。这表明阻塞来自本地 Sandbox 的系统组件环境，而非 FlowHMR 的安装调用逻辑。
   - 排查过程中同步发现并修复了一处真实的启动器缺陷：此前启动器会将注册表中正在卸载的残留项（如 `157.0.4341.42.deleting`）误判为已安装 WebView2，现已改为严格校验可解析且主版本号大于 0 的版本字符串，并补充了 C# 编译回归测试。
2. **本地打包环境的依赖来源**：
   - 本地已从干净源码与固定子模块跑通正式的 `stage` 与 `pack` 打包流程（运行包、源码包及 SHA-256 校验全部通过），但构建环境中的 Python 依赖复制自本地已有的开发环境，尚未在全新机器上跑通“从零下载运行环境 + 下载模型 + 端到端推理”的完整闭环。
   - 此外，本地用于验证更新顺序的 `9.9.90x` 测试版本号仅作内部回归使用，不可用于公开分发。

---

## 2. 建议复测环境与记录项

请使用一台**可正常安装微软运行组件（WebView2）、未预装全局开发环境干扰、且具备可用 NVIDIA GPU** 的干净 Windows 实机或虚拟机进行测试（仅在设备管理器中显示显卡名称但无可用 CUDA 驱动的环境无法用于推理验收）。

测试过程中建议记录以下信息：
- **系统与硬件信息**：Windows 版本号、GPU 型号与驱动版本、内存与可用磁盘空间、系统是否已预装 WebView2（测试首次安装时请勿手动预装 Python 或直接拷入开发机缓存）。
- **测试包身份**：源码提交哈希、子模块提交哈希、打包命令、实际发行版本号及安装包 ZIP 的 SHA-256（建议用同一个候选包跑完下方全部流程；若中途更新了候选包，请标注新包哈希）。
- **关键节点日志**：首次解压启动、运行环境安装、模型下载、动作生成、原片相机恢复及导出的结果与日志（若遇到报错，请区分系统网络/组件问题与程序自身异常）。

## 3. 核心复测清单

| 检查项 | 操作步骤 | 预期结果与通过标准 |
|---|---|---|
| **1. 首次解压与启动** | 在无预装 Python 的干净 Windows 系统中完整解压发行包，双击运行 `FlowHMR.exe` | 随包解释器与 WebView2 正常初始化；主界面完整加载，模型与运行环境管理入口可正常操作；关闭后再次启动正常。 |
| **2. 运行环境与模型下载** | 通过界面安装匹配当前设备的运行环境，并下载所需模型（含 **GeoCalib** 与测试所需的 **HaMeR**） | 不依赖外部开发机缓存；安装自检（`check_install`）与模型哈希校验通过。未下载 GeoCalib 时，原片机位应明确提示“缺少GeoCalib模型，恢复摄像机的地面倾角可能不准确”。 |
| **3. 原路径单镜头生成** | 上传一段未处理过的单镜头视频（固定机位、跨镜头连接保持“自动”但无切镜），按需开启 HaMeR | 完整跑通上传、检测、身体/手部推理、接触修正到 3D 预览的全流程，结果正常播放。 |
| **4. 跨镜头连接生成** | 上传一段包含明确切镜的单人剪辑视频，开启“自动”连接与 HaMeR（请勿复用旧缓存） | 正常识别切镜并完成分段生成；少于 15 帧的碎段及无人区间在时间轴上正确留空；预览播放、中途取消及重试行为符合预期。 |
| **5. 按需恢复原片机位** | 对上述单镜头与跨镜头结果分别点击“视图 → 原片机位”（至少覆盖一个固定机位样本和一个运动机位样本） | 正常调用 GeoCalib 完成地面倾角估计（模拟移走权重时应优雅回退并显示降级提示）；相机解算完成后不改写原人物动作文件；预览中地面倾角、切镜切换与原片画面同步正常。 |
| **6. 配套导出与重启恢复** | 勾选“同时导出相机”，分别导出 NPZ、VMD / FBX 压缩包；随后关闭并重启软件，重新打开历史任务 | 导出的压缩包结构完整，导入 DCC 软件（如 Blender）后时间轴、帧数、角色与机位匹配合理；重启软件后历史任务与用户设置完整保留。 |
| **7. 旧版在线升级与回退** | 准备一份包含真实设置、模型、运行环境、历史输出与自定义角色的官方 `v0.3.6` 安装目录，执行更新至候选版，验证关闭重开与版本回退 | 升级后界面正常就绪，版本号与备份信息准确；原有的模型、环境、角色与历史任务完好无损；手动触发回退或模拟启动故障（45 秒超时）时能自动恢复至上一版本，且日志记录清晰。 |

> **关于非 CUDA 设备的说明**：目前设置页与运行环境界面已明确标注“跨镜头连接”和“原片机位恢复”仅在 NVIDIA CUDA 上完成验证（CPU / AMD ROCm / Intel XPU 标记为尚未验证）。若后续计划扩大官方支持声明，需补充对应硬件的实机测试。

## 4. 启动握手与更新回退机制复核要点

本 PR 针对升级过程中曾偶发的一次“页面就绪超时触发自动回退（同包重试即成功）”进行了专项加固，维护者在审阅或复测时可重点关注以下行为：

- **前端初始化与就绪握手重试**：
  - 页面首次请求本地状态（`/api/info`）失败时最多自动重试 3 次，且每次请求设有明确超时；历史列表与上次任务的启动读取同样受超时保护。
  - 只有当界面核心模块全部初始化完毕后才会向桌面宿主发送就绪通知，且必须收到桌面端的肯定确认；若遇拒绝、异常或无响应会进行有限次重试。若持续失败则绝不写入健康标记，45 秒试运行期满后自动回退至旧版本。
- **分级诊断日志**：
  - `logs/desktop.log` 现已明确区分“已发起页面加载”与“前端界面已确认就绪”，并记录各阶段模块初始化、本地状态读取及早期前端异常。
  - `.cache/program-update/update.log` 专门记录原生启动器在更新替换与版本回退过程中的文件操作详情与异常。
- **文件占用重试与事务保留**：
  - 新版原生启动器在遇到 Windows 短暂文件句柄占用（移动文件被拒绝）时会进行有限次延迟重试；若属于持续性权限/占用失败，则会中止操作并保留当前更新事务，既不破坏已有备份，也不跳过路径安全检查，方便下次启动时继续恢复。
- **旧版 `FlowHMR.exe` 在线更新的固有边界**：
  - 旧版在线更新机制在替换文件时会**保留正在运行的旧版 `FlowHMR.exe` 本体**。因此，Python 后端与前端页面的修复可以直接通过旧版“检查更新”生效；但原生启动器（`FlowHMR.exe`）自身的 WebView2 注册表判断修复与文件移动重试逻辑，必须通过使用**新版完整安装包**才能更新到位。建议在正式 Release Notes 中向用户说明这一迁移方式。

## 5. 常用自动化自检命令

在仓库根目录下激活目标 Python 环境后，可直接运行以下命令进行快速回归检查：

```powershell
python -m unittest discover -s tests -v
node --experimental-vm-modules tools/check_desktop_startup.mjs
node tools/check_locales.mjs
node tools/check_frame_sample.mjs
python tools/windows/check_install.py --json
```
